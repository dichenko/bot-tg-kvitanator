# Тестовое оформление квитанций

Функция доступна только пользователю с Telegram ID из `DAILY_STATS_TELEGRAM_ID`
в личном чате с ботом. При текущей настройке это `19422781`.
Проверка выполняется при показе меню, в обработчиках настройки/загрузки,
при сохранении профиля и при создании снимка оформления новой операции.
В MAX пилот не включён.

## Включение и отключение

```env
DAILY_STATS_TELEGRAM_ID=19422781
RECEIPT_BRANDING_TEST_ENABLED=true
```

`RECEIPT_BRANDING_TEST_ENABLED` по умолчанию равен `true`. Можно отключить
функцию значением `false`: меню станет недоступно, а новые квитанции будут
использовать стандартную шапку. Сохранённые файлы квитанций не изменяются.
Изменение `DAILY_STATS_TELEGRAM_ID` также меняет адресата ежедневной статистики.

Для запуска новой версии нужны генерация Prisma Client, применение миграции
`202611150002_receipt_branding_pilot` и обновление обоих сервисов — бота и
рендерера. Обычный процесс развёртывания уже выполняет сборку и миграции.
Никакие команды миграции не нужно выполнять против production для локальных тестов.

## Пользовательский сценарий

1. Открыть «Данные ИП» → «Оформление квитанции · тест».
2. Загрузить логотип как фотографию или документ PNG/JPEG.
3. При необходимости указать название и подпись. «-» скрывает соответствующий текст.
4. Посмотреть образец и нажать «Сохранить».
5. Создать новую квитанцию обычным способом.

Название заменяет «Квитанатор», подпись заменяет «Сервис генерации квитанций».
Пользовательская картинка заменяет значок в шапке; если нужен только логотип
с уже включённым в него текстом, название и подпись можно оставить пустыми.
Нижняя строка «Сформировано сервисом „Квитанатор“» сохраняется.

Изменения до сохранения остаются черновиком. «Отмена», выход через меню и
повторный `/start` отменяют черновик. После перезапуска бота незавершённый
черновик также теряется; сохранённые настройки остаются в PostgreSQL.
Кнопка «Вернуть стандартное оформление» меняет черновик: для применения
сброса нужно нажать «Сохранить».

Предпросмотр содержит явную отметку «ОБРАЗЕЦ», не создаёт операцию, задание
рендера и номер квитанции. Его временный JPEG удаляется после отправки.

## Картинки и текст

- Статичные PNG и JPEG до 5 МиБ; расширение и MIME не заменяют проверку содержимого.
- Каждая сторона — до 4096 пикселей, всего — до 16 миллионов пикселей.
- Для знака рекомендуется PNG 512 × 512 с прозрачным фоном; для горизонтального
  логотипа — около 800 × 300. Отправка файлом предпочтительна.
- Картинка декодируется и пересохраняется в PNG без исходных метаданных.
  Пропорции и прозрачность сохраняются. Размер нормализованного изображения —
  до 320 × 128 пикселей, область в макете — до 160 × 64.
- SVG, GIF, APNG, PDF и повреждённые файлы не принимаются.
- Название — до 60 символов, подпись — до 120, одной строкой. HTML не исполняется.
- Ошибка загрузки не заменяет предыдущий логотип.

## Хранение

Профиль содержит nullable JSON `receiptBranding`, операция — `brandingSnapshot`.
Все существующие записи после миграции получают SQL NULL и сохраняют стандартный вид.
Новая операция копирует оформление профиля только для разрешённого TGID и канала Telegram.
Рендер использует снимок операции, а история пересылает уже сохранённый JPEG.

Нормализованные PNG лежат в `${RECEIPTS_DIR}/branding/<uuid>.png` в существующем
общем Docker volume `receipts_storage`. Новые настройки создают новые файлы;
версии логотипа не перезаписываются. Рендерер принимает только UUID-имена PNG
из этого каталога и встраивает изображение в HTML, не обращаясь к внешним URL.
Токен бота и ссылки скачивания Telegram не сохраняются в настройках.

При замене картинки в черновике, отмене, сбросе, выходе из редактора и `/start`
неиспользуемая пробная загрузка удаляется. На старте бота очищаются файлы,
оставшиеся от прежних запусков. Затем очистка повторяется каждую минуту:
она сохраняет логотипы текущих профилей, снимков операций и активных черновиков.
Несохранённый черновик удерживает файл до 30 минут бездействия. Для файлов,
которые ранее были сохранены в профиле, предусмотрена защитная пауза 10 минут,
чтобы завершить начатое формирование квитанций. При недоступной БД файлы не удаляются.
Резервировать нужно PostgreSQL и том
`receipts_storage`: существующий predeploy-скрипт автоматически копирует только БД.

## Проверка

```bash
pnpm prisma:generate
pnpm test:branding
pnpm test:stats
```

Без запуска pnpm компиляцию и проверки можно выполнить через
`node scripts/test-branding.cjs` и `node scripts/test-statistics.cjs` после
генерации Prisma Client. Для визуальных проверок нужен Chromium Playwright;
на Windows предусмотрен fallback на установленный Microsoft Edge.

Тесты не используют `.env`, реальную БД или Telegram: Bot API подменяется,
SQL-миграции проверяются в PGlite. В `test-results/branding` сохраняются образцы
стандартной шапки, квадратного и горизонтального логотипов, длинного текста
и предпросмотра.
